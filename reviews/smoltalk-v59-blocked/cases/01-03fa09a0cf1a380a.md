<pre>
The issue you are facing with the slow loading of data when accessing higher offset pages directly is likely due to the size of your table and the way you are retrieving the data. When you try to access the last page, which is towards the end of the table, it takes a long time to load because the database needs to traverse through millions of records to reach the desired offset.

One possible solution to improve the performance is to optimize your SQL query. You can try adding an index on the column you are using for sorting, in this case, the &#x27;id&#x27; column. This can significantly speed up the retrieval process.

Additionally, you can consider implementing server-side pagination. Instead of retrieving all the records at once and then paginating them on the client-side, you can modify your query to fetch only the necessary data for each page. This can be achieved using the SQL LIMIT clause, as you are currently doing. However, instead of retrieving 10 records per page, you can experiment with different page sizes to find the optimal balance between loading time and data retrieval.

Another improvement you can make is to use a more efficient way to count the total number of records. Currently, you are using the count() function, which can be slow for large tables. You can consider using a different approach, such as storing the total count in a separate variable or caching the count result.

Overall, optimizing your SQL query, implementing server-side pagination, and improving the counting method can help improve the performance when accessing higher offset pages in your DataTable.
